Portal Scan

Search 12+ queries across Greenhouse, Lever, Ashby, Dice, LinkedIn, Gov portals
Auto ▼
  1. Read portals.yml — 12 search queries + 30+ tracked companies
  2. Execute WebSearch in parallel batches covering:
    • Greenhouse — PM, Agile, AI roles
    • Lever — PM, Scrum Master, SAFe
    • Ashby — PM, Delivery, AI
    • Dice — Contract TPM, Agile Coach
    • LinkedIn — C2C, 1099 contract roles
    • Gov portals — SAFe, DOT, DOD
    • Construction — Procore-certified PM
  3. Fetch tracked company APIs (Anthropic, Glean Greenhouse boards)
  4. Read data/scan-history.tsv for deduplication
  5. Filter results against title_filter.positive and title_filter.negative keywords
  6. Add new unique URLs to data/pipeline.md under Pending
  7. Append new entries to data/scan-history.tsv

Title Filters

  • Positive: Project Manager, Program Manager, Agile Coach, Scrum Master, SAFe, RTE, Delivery Lead, AI PM, Construction PM
  • Negative: Junior, Intern, Entry Level, Java, .NET, iOS, Blockchain, COBOL
  • Seniority Boost: Senior, Lead, Principal, Staff, Head, Director, VP

Process New Pipeline Entries

Fetch JDs, evaluate with skills-model, generate reports
Auto ▼

For each new URL in data/pipeline.md:

  1. Retrieve job description via WebFetch or Playwright (batch mode falls back to WebSearch)
  2. Verify offer is still active — title + description + Apply button = active; footer only = closed
  3. Run Core Strength Engagement Test against all 7 CS pillars
  4. Score the role using skills-model.md scoring rules (CS weighting, de-emphasis rule, bonuses)
  5. Generate evaluation report in reports/{###}-{company-slug}-{YYYY-MM-DD}.md
  6. Write tracker TSV in batch/tracker-additions/{num}-{company-slug}.tsv
  7. Mark report: **Verification:** unconfirmed (batch mode)
  8. Move URL from Pending to Done in pipeline.md

6

Fit & Application Logic

Process all genuine-fit roles — do NOT over-filter
Decision ▼
  1. Include both Agile + TPM roles when aligned with candidate profile
  2. Do not cap volume — process all strong-fit roles
  3. Apply ethical guardrails: strongly discourage applications below 4.0/5
  4. Respect recruiters' time — only send what's worth reading

Quality Gate

  • Score 4.0+ → Strong fit, proceed with full pipeline
  • Score 3.0–3.9 → Evaluate comp + growth; may proceed with caveats
  • Score <3.0 → Skip unless strategic exception
  • Score 1.0–2.0 → Do not proceed
7

Resume Selection & Tailoring

Match resume type to role, rewrite skills section from cv.md
Auto ▼
  1. Do NOT merge resumes — select one type per role
  2. Agile resume → Agile Coach, Scrum Master, RTE, SAFe roles
  3. Technical PM resume → TPM, Program Manager, Delivery Lead, Cloud/Data/AI roles
  4. Tailor resume per job — rewrite skills section using cv.md only
  5. Summary must always open with CS-1 + CS-2 (never with coaching identity)
  6. Verisk metrics always present: 40% outage reduction, 70% provisioning, 60% stability, ~$3M revenue
  7. BTII (current role) listed last, minimized
  8. Certifications near top: PMP, PMI-ACP, SPC6

Output & Report Generation

Reports, PDFs, tracker TSVs with standardized format
Auto ▼
  1. Reports format: {###}-{company-slug}-{YYYY-MM-DD}.md (3-digit zero-padded, sequential)
  2. Each report labeled: [PRIMARY TARGET ROLE], [SECONDARY TARGET ROLE], or [REJECTED]
  3. Report sections: Role Summary, CV Match, Core Strength Engagement Test, Scoring, Strengths, Gaps & Risks, Recommendation, Resume Selection
  4. All reports include **URL:** in header
  5. Tracker TSV: 9 tab-separated columns per evaluation
  6. Generate tailored PDF via generate-pdf.mjs (Puppeteer)

10

Application Prep

Prepare materials for ALL strong-fit roles — do not cap volume
Decision ▼
  1. Prepare tailored resume PDF for each strong-fit role
  2. Draft cover letter / application answers if needed
  3. Fill application forms (via apply mode) but NEVER auto-submit
  4. Generate STAR stories from interview-prep/story-bank.md for interview prep

Safety Rule

  • NEVER submit applications without candidate review
  • Only prepare + track — user makes the final call
  • Quality over speed: 5 targeted beats 50 generic
11

Tracker Merge & Verification

Merge TSVs into applications.md, verify pipeline integrity
Auto ▼
  1. Run node merge-tracker.mjs — merges all TSVs from batch/tracker-additions/ into data/applications.md
  2. Merged TSVs moved to batch/tracker-additions/merged/
  3. Run node verify-pipeline.mjs — checks canonical statuses, duplicate entries, report links, score format, row format
  4. Run node normalize-statuses.mjs if needed
  5. Run node dedup-tracker.mjs if duplicates found

Commit & Push

Stage all changes, write descriptive commit, push to origin
Auto ▼
  1. Stage all modified and new files (reports, tracker, pipeline, scan history, logs)
  2. Write commit message summarizing: portals scanned, new jobs found, jobs evaluated, applications prepared, primary vs secondary, rejected
  3. Push to designated branch with git push -u origin {branch}
  4. Retry up to 4 times with exponential backoff on network failure
