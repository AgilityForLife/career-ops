How Career-Ops Works

A step-by-step walkthrough of how the AI pipeline scans job portals, fetches descriptions, evaluates fit, scores roles, generates reports, and tracks applications — end to end.

Step 1 — Setup

Load the Brain

Before any scanning happens, the system reads three files that tell it who you are, what you're good at, and what you're looking for. Nothing runs without this context.

🧠 Three files loaded every session

  • config/skills-model.md — The decision framework. Defines 7 Core Strengths (CS-1 through CS-7) that every job is scored against. Contains scoring formulas, resume rules, interview strategy, and de-emphasis rules for Tier 4 skills.
  • config/profile.yml — Your identity: name, location (NJ), target roles (Senior TPM, Agile Coach, Scrum Master), comp targets ($60+/hr C2C, $100K+ FTE), deal-breakers (no relocation, no on-site 5 days/week).
  • cv.md — Your canonical resume. Every metric, every proof point comes from here. The system never invents data. If cv.md says "40% outage reduction" that's what goes on the resume — no rounding up to 50%.
🔒

Positioning Lock: The system always leads with CS-1 (enterprise delivery at scale) + CS-2 (AWS + Snowflake). It never leads with Agile coaching identity, Salesforce admin, or non-profit work — unless you explicitly override this.

Step 2 — Scan Configuration

Build the Search Queries

The system reads portals.yml, which defines exactly what to search for and where. This file contains 12 search query templates and 30+ tracked companies.

🔍 What portals.yml contains

  • Title filters (positive) — Keywords that match target roles: "Project Manager", "Agile Coach", "Scrum Master", "SAFe", "RTE", "Delivery Lead", "AI Project Manager", "Construction Project Manager", etc.
  • Title filters (negative) — Keywords to reject: "Junior", "Intern", "Entry Level", "Java", ".NET", "iOS", "Blockchain", "COBOL".
  • Seniority boost — Titles containing "Senior", "Lead", "Principal", "Director" get priority.
  • 12 search query templates — Pre-built Google-style searches targeting specific job board domains.
  • 30+ tracked companies — Enterprise tech (IBM, AWS, Google), consulting (Accenture, Deloitte, KPMG), finance (JPMorgan, Citi, Prudential), pharma (J&J, Merck), AI (Anthropic, OpenAI, Palantir), gov (WSP, AECOM, Parsons).
Example Search Query

site:boards.greenhouse.io "Technical Project Manager" OR "Program Manager" OR "Delivery Lead" remote OR "New Jersey" OR "New York"

Step 3 — Portal Scanning

Hit the Websites

This is where the system actually goes out to the internet. It runs each search query using WebSearch (a Google-style search API) and collects job listing URLs from the results.

🌐 How it searches (parallel batches)

  • Batch 1: Greenhouse boards — PM, Delivery Lead, Agile Coach, Scrum Master roles across all Greenhouse-hosted job boards
  • Batch 2: Ashby & Lever — PM, Agile, AI roles on these ATS platforms
  • Batch 3: AI-specific — "AI Project Manager", "AI Program Manager", "AI Transformation", "Digital Transformation"
  • Batch 4: PMO, Portfolio Manager, Release Manager roles
  • Batch 5: Contract roles — C2C, 1099, freelance PM/SM roles on LinkedIn, Dice
  • Batch 6: Government — SAFe + Agile in federal/DOT/DOD programs
  • Batch 7: Construction PM — Procore-certified roles in NJ/NY
  • Batch 8: Tracked company APIs — Direct API calls to Greenhouse boards (Anthropic, Glean, etc.)

Step 5 — Title Filtering

Apply Title Filters & Quick Triage

Not every URL from a search is worth evaluating. The system applies positive/negative keyword filters and does a quick triage based on the job title, location, and any obvious disqualifiers.

✂️ Quick rejection criteria

  • Location mismatch — Philippines, India, UK-only roles rejected immediately
  • Clearance required — Secret/Top Secret clearance roles flagged and usually rejected
  • Wrong seniority — Junior, Intern, Entry Level filtered by negative keywords
  • Wrong domain — Specific tech requirements that don't match (e.g., "2+ years Google CCAI" or "Market Risk domain")
  • Job closed — Listings confirmed as removed or expired

Step 6 — JD Retrieval

Fetch the Full Job Descriptions

For each role that survives filtering, the system tries to retrieve the full job description. It uses multiple methods depending on availability.

📥 Retrieval methods (in priority order)

  • Method 1: Playwright (preferred) — Opens a real browser, navigates to the URL, takes a snapshot. Most accurate. Verifies the listing is still active (title + description + Apply button = active). Not available in batch/headless mode.
  • Method 2: WebFetch — HTTP fetch of the URL, converts HTML to markdown. Faster but can be blocked by 403 Forbidden responses from job boards.
  • Method 3: Greenhouse API — Direct JSON API calls to boards-api.greenhouse.io/v1/boards/{company}/jobs/{id}. Only works for Greenhouse-hosted jobs.
  • Method 4: WebSearch (fallback) — When direct fetching is blocked, uses targeted Google searches to find JD details on third-party aggregators (RemoteRocketship, Himalayas, BuiltIn, Startup.jobs) that mirror job postings.
⚠️

Reality check: Many job board sites (Greenhouse, Lever, Ashby) block automated fetching with 403 errors. When this happens, evaluations are based on search snippets and marked **Verification:** unconfirmed (batch mode).

Step 7 — Evaluation

Run the Core Strength Engagement Test

This is the heart of the system. For every job, the evaluator checks how many of the candidate's 7 Core Strengths the role engages. This produces the base score.

Modifiers applied after base score:

  • CS-1 absent → cap at 3.5
  • CS-2 absent → -0.3
  • CS-4 present → +0.2 bonus
  • CS-6 explicitly required → +0.2 bonus
  • Tier 4 skills primary → cap at 3.0

Step 9 — Report Generation

Generate Evaluation Reports

For every role that's not rejected, the system generates a detailed evaluation report in markdown. Each report follows a standardized structure.

📝 Report structure

  • Header — Date, Archetype, Score, URL, PDF status, Verification status, Classification tag
  • A) Role Summary — Table with archetype, domain, function, seniority, remote/hybrid, contract type, salary, TL;DR
  • B) CV Match — Side-by-side table: JD requirement vs. candidate's matching experience from cv.md
  • C) Core Strength Engagement Test — All 7 CS checked with ✔/⚠/❌ and notes
  • D) Scoring — Base score, modifiers applied, final score
  • E) Strengths — What makes this a good fit
  • F) Gaps & Risks — Honest assessment of weaknesses
  • G) Recommendation — PROCEED / PROCEED WITH CAUTION / SKIP
  • H) Resume Selection — Which resume type, why, what to lead with
# Report naming convention: reports/007-nava-sr-project-manager-2026-05-19.md reports/008-mercury-senior-tpm-2026-05-19.md reports/009-rula-tpm-2026-05-19.md # Format: {###}-{company-slug}-{YYYY-MM-DD}.md # Number: 3-digit zero-padded, sequential (max existing + 1)

📄 Resume rules (always enforced)

  • Summary always opens with CS-1 + CS-2 (enterprise delivery + cloud/data)
  • Never opens with coaching identity
  • Verisk headline metrics always present: 40% outage reduction, 70% provisioning, 60% stability, ~$3M revenue
  • BTII (current role) listed last, minimized
  • Certifications near top: PMP, PMI-ACP, SPC6
  • Skills section rewritten per job using cv.md only
  • Tier 4 skills excluded by default

Step 13 — Logging

Write Session Log

Every pipeline run produces a structured session log for continuous self-improvement. The log captures what happened, what worked, what failed, and what to do differently next time.

📅 Session log structure

  • Execution Summary — Portals scanned, jobs found, evaluated, prepared
  • Key Decisions — Important choices made
  • What Worked / Failed / Friction — Honest assessment
  • Missing Context — What would have helped
  • Reusable Insight — Patterns for future optimization
  • Top Mistake / Improvement Opportunity — Highest-leverage learnings
Step 14 — Ship It

Commit & Push

All changes are committed with a descriptive message summarizing the entire run, then pushed to the remote branch.

git add data/ reports/ logs/ batch/ verify-pipeline.mjs git commit -m "Daily pipeline scan 2026-05-19: 21 new jobs, 8 evaluated, 5 rejected Evaluated (8): - Rula TPM (3.9/5) -- remote, data platform, healthcare [SECONDARY] - Mercury Sr TPM (3.8/5) -- remote, fintech, $118K-$148K [SECONDARY] - Nava Sr PM (3.7/5) -- NJ hybrid, government [SECONDARY] - Neon One Agile DM (3.5/5) -- remote, leads SMs [PRIMARY] ..." git push -u origin claude/feature-branch
🛡️

Safety rule: The pipeline NEVER auto-submits applications. It prepares materials (reports, PDFs, tracker entries) and stops. The candidate always makes the final call on whether to apply.
